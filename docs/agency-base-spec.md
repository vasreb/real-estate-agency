# Спецификация базовой системы агентства недвижимости

Внутреннее приложение показывает сотруднику сделки его команд, связанные объекты и документы. Администратор команды управляет файлами сделок. Одна сделка относится к одному клиенту, одному объекту и одной команде. У клиента и объекта может быть несколько сделок.

**Стек.** Next.js + TypeScript для интерфейса и отдельный Fastify + TypeScript для HTTP API. PostgreSQL хранит данные, сессии и оригиналы файлов. Для небольшого архива оригинал хранится в `bytea`, поэтому файл и его метаданные можно добавить или удалить в одной транзакции. [Тип `bytea` в PostgreSQL](https://www.postgresql.org/docs/current/datatype-binary.html)

## Данные

Идентификаторы сущностей — UUID. Поля обязательны, кроме явно отмеченных как необязательные. Даты документа хранятся как `date`, время загрузки файла и истечения сессии — как `timestamptz`.

| Таблица        | Поля и связи                                                                                                                                                                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`        | `id`, уникальный нормализованный `email`, `password_hash`.                                                                                                                                                                                                                                                                                                                       |
| `sessions`     | `token_hash` — первичный ключ, `user_id` → `users`, `expires_at`.                                                                                                                                                                                                                                                                                                                |
| `teams`        | `id`, `name`.                                                                                                                                                                                                                                                                                                                                                                    |
| `team_members` | `team_id` → `teams`, `user_id` → `users`, `role` (`member` или `admin`). Первичный ключ — пара `team_id`, `user_id`. Роль действует в пределах команды.                                                                                                                                                                                                                          |
| `clients`      | `id`, `name` — имя клиента или название организации.                                                                                                                                                                                                                                                                                                                             |
| `properties`   | `id`, `address`.                                                                                                                                                                                                                                                                                                                                                                 |
| `deals`        | `id`, `number` — текстовый номер, уникальный в команде, `type` (`sale` или `rental`), `client_id` → `clients`, `property_id` → `properties`, `team_id` → `teams`.                                                                                                                                                                                                                |
| `documents`    | `id`, `deal_id` → `deals`, необязательный `parent_document_id` → `documents`, `type` (`contract`, `amendment`, `listing_sheet`, `handover_report` или `other`), `title`, необязательные `document_number`, `document_date`, `effective_from`, `status` (`draft`, `signed` или `unknown`, по умолчанию `unknown`), `file_name`, `mime_type`, `file_data` (`bytea`), `created_at`. |

Одна запись в `documents` соответствует одному файлу. `parent_document_id` заполняется у допсоглашения, когда известно, к какому договору оно относится. Сервер проверяет, что родитель имеет тип `contract`. База проверяет, что оба документа относятся к одной сделке, через составной внешний ключ `(deal_id, parent_document_id)` на уникальную пару `(deal_id, id)`. Запретить ссылку на самого себя и удаление договора, пока на него ссылаются допсоглашения. [Ограничения PostgreSQL](https://www.postgresql.org/docs/current/ddl-constraints.html)

Создать индексы `team_members(user_id)` и `documents(deal_id, parent_document_id)`. Пользователей, команды, участников, клиентов, объекты и сделки в первой версии заводят через скрипт начального заполнения базы. В интерфейсе эти записи доступны для просмотра через сделки.

## Вход и права

- Вход по email и паролю. Сервер хранит хеш пароля Argon2id. При входе создаёт случайный токен сессии, хранит его хеш в PostgreSQL и устанавливает cookie `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS. При выходе удаляет сессию и очищает cookie. Для входа ограничивает частоту попыток, для изменяющих запросов проверяет источник запроса. [Управление сессиями OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [Хранение паролей OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- `member` видит сделки своей команды, связанные сведения о клиенте и объекте и может скачать документы. `admin` обладает теми же правами и может загружать, редактировать и удалять документы в сделках этой команды.
- Сервер проверяет членство при каждом запросе к сделке и при каждом обращении к документу. Для документа команда определяется через `documents.deal_id` и `deals.team_id`. У пользователя может быть несколько команд. Права вычисляются по текущим записям `team_members`.

## HTTP API

| Метод и путь                           | Поведение                                                                                                                                                                                                                                     |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/auth/login`                 | Принимает `{ email, password }`, создаёт сессию, устанавливает cookie. Успех `204`.                                                                                                                                                           |
| `POST /api/auth/logout`                | Завершает текущую сессию и очищает cookie. Успех `204`.                                                                                                                                                                                       |
| `GET /api/deals`                       | Возвращает `{ items }`. В каждой строке `id`, номер и тип сделки, имя клиента, адрес и название команды. Выборка ограничена командами пользователя.                                                                                           |
| `GET /api/deals/{dealId}`              | Возвращает сделку, клиента, объект, команду, роль пользователя в команде и метаданные документов.                                                                                                                                             |
| `POST /api/deals/{dealId}/documents`   | Администратор загружает `multipart/form-data` с файлом и метаданными. Обязательны `file`, `title` и `type`. Остальные поля — `document_number`, `document_date`, `effective_from`, `status`, `parent_document_id`. Успех `201` с метаданными. |
| `GET /api/documents/{documentId}/file` | После проверки доступа отдаёт оригинал как вложение с исходным именем файла.                                                                                                                                                                  |
| `PATCH /api/documents/{documentId}`    | Администратор обновляет название, номер, даты, статус и ссылку на договор. Отсутствующие поля сохраняют значения. `null` очищает необязательное поле. Успех `200` с обновлёнными метаданными.                                                 |
| `DELETE /api/documents/{documentId}`   | Администратор удаляет документ вместе с оригиналом. Успех `204`. Если у договора есть связанные допсоглашения, сервер возвращает `409`.                                                                                                       |

Загрузка принимает PDF и DOCX размером до 25 МБ. Сервер проверяет содержимое файла и размер до записи. Ответы со списками и метаданными исключают `file_data`. Для ошибок API возвращает `{ code, message }`. Основные коды HTTP — `400` для некорректных данных, `401` для отсутствующей сессии или неверных данных входа, `403` при недостаточной роли в своей команде, `404` для отсутствующей или чужой записи, `413` для превышения размера, `415` для неподдерживаемого формата и `429` при превышении лимита попыток входа.

## Экраны

| Экран                           | Содержимое                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/login` — вход                 | Поля email и пароля, кнопка «Войти», сообщение об ошибке. После входа — переход к списку сделок.                                                                                                                                                                                                                                                                                                                                   |
| `/deals` — сделки               | Таблица с номером, типом сделки, клиентом, адресом объекта и командой. Строка открывает карточку. Пустой список показывает «Нет доступных сделок». В шапке есть кнопка выхода.                                                                                                                                                                                                                                                     |
| `/deals/[id]` — карточка сделки | Номер и тип сделки, клиент, адрес объекта и команда. В разделе «Документы» видны название, тип, номер, дата, статус, дата вступления в силу и связанный договор. У каждой записи есть «Скачать». Администратор видит «Загрузить», «Редактировать» и «Удалить». Формы открываются на той же странице. Для допсоглашения можно выбрать договор из этой сделки или оставить поле пустым. Удаление требует подтверждения в интерфейсе. |

## Приёмка

1. В тестовых данных есть две команды с разными сделками, администратор и сотрудник первой команды, сотрудник второй команды, договор и допсоглашение.
2. Каждый пользователь видит сделки своих команд. По прямому URL чужой сделки и через API чужого документа сервер возвращает `404`.
3. Сотрудник скачивает файл своей команды. Попытка изменить документ через API возвращает `403`.
4. Администратор загружает PDF или DOCX, привязывает допсоглашение к договору той же сделки и скачивает оригинал. Ссылка на договор из другой сделки отклоняется.
5. Договор со связанным допсоглашением защищён от удаления. После удаления допсоглашения его оригинал недоступен по прежнему адресу.
