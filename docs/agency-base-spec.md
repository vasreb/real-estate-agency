# Real Estate Agency Base System Specification

The internal application shows an employee the deals of their teams, the linked properties, and the documents. A team administrator manages the deal files. One deal belongs to one client, one property, and one team. A client or property can have several deals.

**Stack.** Next.js + TypeScript for the interface and a separate Fastify + TypeScript HTTP API. PostgreSQL stores the data, sessions, and original files. For a small archive, the original is stored in `bytea`, so a file and its metadata can be added or deleted in one transaction. [PostgreSQL `bytea` type](https://www.postgresql.org/docs/current/datatype-binary.html)

## Data

Entity identifiers are UUIDs. Fields are required unless explicitly marked as optional. Document dates are stored as `date`; file upload and session expiry times are stored as `timestamptz`.

| Table          | Fields and relations                                                                                                                                                                                                                                                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`        | `id`, unique normalized `email`, `password_hash`.                                                                                                                                                                                                                                                                                                               |
| `sessions`     | `token_hash` — primary key, `user_id` → `users`, `expires_at`.                                                                                                                                                                                                                                                                                                  |
| `teams`        | `id`, `name`.                                                                                                                                                                                                                                                                                                                                                   |
| `team_members` | `team_id` → `teams`, `user_id` → `users`, `role` (`member` or `admin`). Primary key — the pair `team_id`, `user_id`. The role applies within the team only.                                                                                                                                                                                                     |
| `clients`      | `id`, `name` — client's name or organization name.                                                                                                                                                                                                                                                                                                              |
| `properties`   | `id`, `address`.                                                                                                                                                                                                                                                                                                                                                |
| `deals`        | `id`, `number` — text number, unique within the team, `type` (`sale` or `rental`), `client_id` → `clients`, `property_id` → `properties`, `team_id` → `teams`.                                                                                                                                                                                                  |
| `documents`    | `id`, `deal_id` → `deals`, optional `parent_document_id` → `documents`, `type` (`contract`, `amendment`, `listing_sheet`, `handover_report`, or `other`), `title`, optional `document_number`, `document_date`, `effective_from`, `status` (`draft`, `signed`, or `unknown`, default `unknown`), `file_name`, `mime_type`, `file_data` (`bytea`), `created_at`. |

Each row in `documents` corresponds to one file. `parent_document_id` is set for an amendment when it is known which contract it belongs to. The server checks that the parent has type `contract`. The database checks that both documents belong to the same deal via the composite foreign key `(deal_id, parent_document_id)` referencing the unique pair `(deal_id, id)`. Self-references are forbidden, and a contract cannot be deleted while amendments reference it. [PostgreSQL constraints](https://www.postgresql.org/docs/current/ddl-constraints.html)

Create the indexes `team_members(user_id)` and `documents(deal_id, parent_document_id)`. In the first version, users, teams, members, clients, properties, and deals are created through the database seed script. In the interface these records are only visible through deals.

## Sign-in and permissions

- Sign in with email and password. The server stores an Argon2id password hash. On sign-in it creates a random session token, stores its hash in PostgreSQL, and sets an `HttpOnly`, `SameSite=Lax` cookie, plus `Secure` over HTTPS. On sign-out it deletes the session and clears the cookie. Sign-in attempts are rate-limited, and state-changing requests verify the request origin. [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- `member` can see the deals of their team, the related client and property details, and can download documents. `admin` has the same rights and can upload, edit, and delete documents in that team's deals.
- The server checks membership on every deal request and on every document access. For a document, the team is determined via `documents.deal_id` and `deals.team_id`. A user can belong to several teams. Permissions are computed from the current `team_members` records.

## HTTP API

| Method and path                        | Behavior                                                                                                                                                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/auth/login`                 | Accepts `{ email, password }`, creates a session, sets the cookie. Success `204`.                                                                                                                                                                  |
| `POST /api/auth/logout`                | Ends the current session and clears the cookie. Success `204`.                                                                                                                                                                                     |
| `GET /api/deals`                       | Returns `{ items }`. Each row contains `id`, deal number and type, client name, property address, and team name. Results are limited to the user's teams.                                                                                          |
| `GET /api/deals/{dealId}`              | Returns the deal, client, property, team, the user's role in the team, and document metadata.                                                                                                                                                      |
| `POST /api/deals/{dealId}/documents`   | An administrator uploads `multipart/form-data` with the file and metadata. Required: `file`, `title`, and `type`. Other fields: `document_number`, `document_date`, `effective_from`, `status`, `parent_document_id`. Success `201` with metadata. |
| `GET /api/documents/{documentId}/file` | After the access check, returns the original as an attachment with its original file name.                                                                                                                                                         |
| `PATCH /api/documents/{documentId}`    | An administrator updates the title, number, dates, status, and contract link. Missing fields keep their values. `null` clears an optional field. Success `200` with updated metadata.                                                              |
| `DELETE /api/documents/{documentId}`   | An administrator deletes the document together with its original. Success `204`. If a contract has linked amendments, the server returns `409`.                                                                                                    |

Uploads accept PDF and DOCX files up to 25 MB. The server checks the file content and size before writing. List and metadata responses exclude `file_data`. API errors return `{ code, message }`. The main HTTP codes are: `400` for invalid data, `401` for a missing session or invalid sign-in data, `403` for insufficient role in the team, `404` for a missing or foreign record, `413` for a size limit violation, `415` for an unsupported format, and `429` when the sign-in attempt limit is exceeded.

## Screens

| Screen                    | Content                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/login` — sign in        | Email and password fields, a "Sign in" button, and an error message. After signing in, the user goes to the deals list.                                                                                                                                                                                                                                                                                                                         |
| `/deals` — deals          | Table with number, deal type, client, property address, and team. A row opens the deal card. An empty list shows "No available deals". The header has a sign-out button.                                                                                                                                                                                                                                                                        |
| `/deals/[id]` — deal card | Deal number and type, client, property address, and team. In the "Documents" section, the title, type, number, date, status, effective date, and related contract are shown. Each record has a "Download" action. An administrator sees "Upload", "Edit", and "Delete". Forms open on the same page. For an amendment, the user can select a contract from this deal or leave the field empty. Deletion requires confirmation in the interface. |

## Acceptance

1. The test data contains two teams with different deals, an administrator and an employee of the first team, an employee of the second team, a contract, and an amendment.
2. Each user sees the deals of their teams. Requesting a foreign deal by direct URL, or a foreign document through the API, returns `404`.
3. An employee downloads a file from their own team. An attempt to modify a document through the API returns `403`.
4. An administrator uploads a PDF or DOCX, links an amendment to a contract of the same deal, and downloads the original. A reference to a contract from another deal is rejected.
5. A contract with a linked amendment is protected from deletion. After the amendment is deleted, its original is no longer available at the same address.
